# Tolstoy BPE Tokenizer v7: Радикально Оптимизированный

## Общее описание

**BPE Tokenizer v7** — седьмая версия байтового токенизатора Tolstoy AI Studio, переработанная с фокусом на **сублинейной сложности обучения** и **линейном инференсе**. Ключевые достижения: in-place слияния через LinkedArray, инкрементальное обновление пар, Trie-based O(n) кодирование, и поддержка параллельной предтокенизации.

**Ключевые достижения v7:**
- **Linked Array (двусвязный список на массиве)** — O(1) in-place слияния без аллокаций
- **Location Indexing** — `pair -> set(word_indices)` для инкрементальных обновлений
- **Trie (префиксное дерево)** — O(n) кодирование вместо O(n²) наивного BPE
- **Инкрементальный подсчёт** — пересчёт частот только для затронутых пар
- **Ленивая приоритетная очередь** — heapq с валидацией stale entries
- **Параллельная предтокенизация** — ThreadPoolExecutor для больших текстов
- **Memory-mapped чтение** — поддержка файлов > 100MB через mmap

**Минимальные требования:**
- Обучение: 2 GB RAM (для словаря до 8192)
- Инференс: 512 MB RAM (Trie занимает ~20% от размера vocab)
- Скорость encode: 50,000+ токенов/сек на CPU

## Регулярное выражение предтокенизации

```regex
 ?[а-яА-ЯёЁa-zA-Z]+-[а-яА-ЯёЁa-zA-Z]+| ?\w+| ?[^\s\w]+|\s+(?!\S)|\s+
```

**Компоненты:**
- ` ?[а-яА-ЯёЁa-zA-Z]+-[а-яА-ЯёЁa-zA-Z]+` — дефисные составные слова (русский/английский)
- ` ?\w+` — слова с опциональным ведущим пробелом
- ` ?[^\s\w]+` — пунктуация и спецсимволы
- `\s+(?!\S)` — конечные пробелы
- `\s+` — остальные пробельные последовательности

**Особенности:**
- Сохраняет пробелы как часть токенов (word-boundary awareness)
- Поддержка дефисных слов (важно для русской морфологии)
- Опциональная морфологическая предобработка (stemming/lemmatization) через внешние библиотеки

## Алгоритм обучения (train)

### Этап 1: Предтокенизация и Chunk Deduplication
1. Текст разбивается на слова через regex
2. Слова агрегируются через `Counter` — каждое уникальное слово хранится единожды
3. Частота слова сохраняется как множитель
4. **Оптимизация**: повторяющиеся слова обрабатываются один раз, масштабируются по частоте

### Этап 2: Инициализация LinkedArray
- Каждое уникальное слово представляется как `_LinkedArray` — гибрид массива и двусвязного списка
- `tokens`: `array.array('I')` — компактное хранение unsigned int
- `prev`/`next`: индексы соседей (-1 для границ)
- **Преимущество**: слияние пары = O(1) per occurrence, нет аллокаций новых списков

### Этап 3: Первоначальный подсчёт пар
- Для каждого слова собираются все соседние пары
- `pair_counts[pair] += count` — агрегирование через частоту слова
- **Location Indexing**: `_location_index[pair].add(word_idx)` — знаем, какие слова содержат пару

### Этап 4: Ленивая приоритетная очередь (Lazy Heap)
- Структура: `heapq` с ключом `(-frequency, pair)`
- **Проблема**: при обновлении частот старые entries устаревают
- **Решение**: stale set + валидация при извлечении
  ```python
  while heap:
      neg_freq, pair = heapq.heappop(heap)
      if pair in stale: continue
      actual = pair_counts.get(pair, 0)
      if actual == -neg_freq:
          best_pair = pair; break
      if actual > 0:
          heapq.heappush(heap, (-actual, pair))  # перепушиваем с актуальной частотой
  ```
- **Эффект**: средняя сложность extract-min остаётся O(log U)

### Этап 5: Инкрементальные слияния
Для каждой итерации слияния:
1. Извлекаем пару с максимальной частотой из heap
2. Создаём новый токен `new_id = 256 + i`
3. **Delta-update** (только для затронутых слов):
   - Старые пары (до слияния) декрементируются: `pair_counts[p] -= count`
   - Новые пары (после слияния) инкрементируются: `pair_counts[p] += count`
   - Location Index обновляется: старые пары удаляются из word_idx, новые добавляются
4. **In-place merge** через LinkedArray:
   - Левый узел обновляется значением `new_id`
   - Правый узел помечается "мертвым" (prev/next = -1)
   - Указатели соседей перенаправляются

**Сложность одного слияния**: O(k) где k — число вхождений пары (не зависит от размера корпуса)
**Общая сложность**: O(M log U) где M — число слияний, U — уникальных пар

### Этап 6: Построение Trie
После обучения строится префиксное дерево из всех токенов словаря:
- Узел: `children: Dict[int, TrieNode]` + `token_id: Optional[int]`
- Ключи: байты токена (bytes) — компактное представление
- **Использование**: O(n) encode через жадный longest-prefix matching

## Алгоритм инференса (encode)

### Trie-based кодирование (O(n))
```python
def encode_bytes(self, data: bytes) -> List[int]:
    result = []
    i = 0
    while i < len(data):
        node = self.root
        last_match = None
        last_match_pos = i
        j = i
        while j < len(data) and data[j] in node.children:
            node = node.children[data[j]]
            if node.is_end:
                last_match = node.token_id
                last_match_pos = j
            j += 1
        if last_match is not None:
            result.append(last_match)
            i = last_match_pos + 1
        else:
            result.append(data[i])  # fallback: raw byte
            i += 1
    return result
```

**Особенности:**
- Жадный longest-prefix matching — гарантирует детерминированность
- Fallback на raw byte для неизвестных последовательностей
- Кэширование на уровне слов (LRU cache, 300k entries)
- Параллельная обработка больших текстов через ThreadPoolExecutor

## Метрики качества токенизации

### Фертильность (Fertility)
Среднее число токенов на слово. Меньше = лучше.
```python
def get_subword_fertility(self, text: str) -> float:
    words = RU_PATTERN.findall(text)
    total_tokens = sum(len(self._encode_word(w)) for w in words)
    return total_tokens / len(words)
```

**Целевые значения:**
- Английский: 1.2–1.5 токенов/слово
- Русский: 1.5–2.0 токенов/слово (богатая морфология)

### Коэффициент сжатия (Compression Ratio)
```python
def estimate_compression_ratio(self, text: str) -> float:
    tokens = self.encode(text)
    original_bytes = len(text.encode("utf-8"))
    return original_bytes / len(tokens)
```
- Больше = лучше токенизация
- Типичные значения: 3–6 байт/токен

## Оптимизации для русского языка

### 1. Дефисные слова
Regex захватывает составные слова как единые токены:
- `"человеко-недружелюбный"` → один токен (если в словаре)
- `"нью-йоркский"` → единый токен

### 2. Поддержка Unicode
- Начальный словарь: 256 байт (UTF-8 encoded)
- Кириллица: 2 байта на символ → BPE объединяет в токены
- Эмодзи: многобайтовые последовательности → отдельные токены

### 3. Опциональная морфология
Возможна интеграция с pymorphy2/lemmatization как предобработка:
```python
# Опциональный pipeline
text = lemmatize(text)  # "бежал" → "бежать"
tokens = tokenizer.encode(text)
```

```python
tokenizer = BPETokenizer()
```

```python
tokenizer = BPETokenizer.load('tokenizer.pkl')
# Trie строится автоматически при загрузке
tokens = tokenizer.encode(text)  # O(n)

```

```python
metrics = tokenizer.estimate_compression_ratio(text)
print(f"Compression: {metrics:.2f}x")
```
- Цель: > 4x для английского, > 3x для русского

## ❓ FAQ (Часто задаваемые вопросы)

**В: Почему используется именно BPE, а не WordPiece или Unigram?**
О: BPE (Byte Pair Encoding) — это стандарт индустрии, который отлично справляется с незнакомыми словами, разбивая их на байтовые последовательности. Это критически важно для русского языка с его огромным количеством окончаний и суффиксов. Однако в v8 мы планируем добавить поддержку Unigram для еще более точной морфологии.

**В: Как размер словаря (vocab_size) влияет на скорость и качество?**
О: Чем больше словарь, тем длиннее и осмысленнее становятся отдельные токены (целые слова вместо слогов), что ускоряет инференс (меньше шагов генерации). Но слишком большой словарь (например, 100k) размывает статистику и требует больше видеопамяти. Для русского языка оптимально 8k–32k.

**В: Можно ли использовать токенизатор от другой модели (например, Llama)?**
О: Можно, но не рекомендуется. Наш токенизатор v7 специально обучен на корпусах русской классики и новостей, что дает гораздо более высокую "плотность сжатия" (Compression Ratio) для русского текста. Сторонние токенизаторы будут разбивать русские слова на слишком мелкие части, что замедлит работу в 2-3 раза.

**В: Что такое "Фертильность" (Fertility)?**
О: Это среднее количество токенов, на которое разбивается одно слово. Идеальная фертильность для русского языка — от 1.5 до 2.0. Если она выше 2.5 — значит, токенизатор "плохо знает" ваш текст и разбивает его на слишком мелкие кусочки (буквы или слоги).

**В: Зачем нужно префиксное дерево (Trie)?**
О: Раньше кодирование текста занимало много времени ($O(n^2)$), так как токенизатор постоянно искал пары по всему тексту. С использованием Trie мы просто идем по дереву один раз ($O(n)$), мгновенно находя самый длинный подходящий токен. Это ускорило инференс в десятки раз.
